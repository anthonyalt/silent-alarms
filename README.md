# Silent Alarms

A native Android app scaffold built with Kotlin, Jetpack Compose, and Material 3
Expressive. Requires Android 8.0 (API 26) or newer; compiles and targets API 36.
Package: `nz.silentalarms.app`.

The app currently supports local alarm creation, editing, enable/disable
toggling, and swipe-to-delete with undo. Alarms are stored in Room and survive
app restarts. Enabled alarms use exact `AlarmManager` scheduling, survive device
reboots, and fire through a foreground service with a lock-screen UI, repeating
vibration, nine-minute snooze, and five-minute auto-dismiss. Sound playback is
not implemented yet.

## Build

Install JDK 17 and the Android SDK command-line tools (or Android Studio), then
install platform 36 and build-tools 35.0.0:

```sh
sdkmanager "platforms;android-36" "build-tools;35.0.0"
sdkmanager --licenses
```

Set `JAVA_HOME` to your JDK 17 and `ANDROID_HOME` to your SDK directory, or put
`sdk.dir=/absolute/path/to/Android/sdk` in an untracked `local.properties`.
The checked-in wrapper downloads Gradle 8.13 on first use.

```sh
./gradlew assembleDebug
./gradlew testDebugUnitTest
```

The APK is written to `app/build/outputs/apk/debug/app-debug.apk`. With an Android
device connected and `adb` installed, install it with:

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## Project layout

- `app/src/main/java/nz/silentalarms/app/ui`: list/editor UI, ViewModel state,
  and Expressive theme.
- `app/src/main/java/nz/silentalarms/app/data`: Room entity, converters, DAO,
  database, and the Preferences DataStore delegate.
- `app/src/main/java/nz/silentalarms/app/scheduler`: exact alarm scheduling.
- `app/src/main/java/nz/silentalarms/app/service` and `receiver`: alarm firing,
  notification/vibration lifecycle, and reboot recovery.
- `app/schemas`: versioned Room schemas generated by KSP.
- `gradle/libs.versions.toml`: pinned dependency and plugin versions.

`SilentAlarmsApplication` owns the lazy database and settings store. The UI
persists alarm edits through a ViewModel and `StateFlow`; settings UI is not
implemented yet. Material 3 uses `1.5.0-alpha12` explicitly because its
Expressive APIs are not part of stable `1.4.0`; other Compose libraries use the
pinned BOM.

## Automated APK delivery

Every push to `main` runs `.github/workflows/build.yml` with JDK 17, builds the
debug APK, and runs unit tests. The APK is available as the
`silent-alarms-debug` Actions artifact (14-day retention) and as an asset on a
GitHub prerelease tagged `build-<run number>-<attempt>`. Each release targets the
exact built commit; reruns get a separate tag.

These APKs are debug-signed development builds, not production releases.
GitHub-hosted runners may use different debug signing keys across runs, so
installing a later build can require uninstalling the old one (which removes
local data).
